# 阶段 4：自动换挡（RACE 模式）

**这一阶段只做一件事：让它自己换挡。** 不学功率曲线、不认车辆、不做多模式。

---

## 一、先看安全设计

| 机制 | 行为 |
|---|---|
| **默认关闭** | 启动时自动换挡是关的，必须按 **F11** 才启用 |
| **F11** | 启用 / 停用（随时切换，不需要退出） |
| **F12** | 硬急停：退出并释放按键 |
| **遥测断流 300ms** | 立即停手，画面显示"断流（已停手）" |
| **换挡中（档位 11）** | 不发任何指令 |
| **上一条没确认** | 不发下一条 |
| **冷却 250ms** | 每次换挡后强制等待（实测换挡耗时 70–150ms） |

违反任何一条，宁可**不换**，也不在错误时刻换。少换一次只是慢一点，换错一次可能就打滑或超转。

---

## 二、运行

双击 **`tools\自动换挡.bat`**。启动脚本已带 `--overlay`，会在左上角显示浮窗：

```
3 挡   7418 rpm   153 km/h
UP 达到升挡转速 (89.2% ≥ 89.0%)
换挡 12/12 成功  中位 104ms  超时 0
F11 启用/停用   F12 退出
```

画面会显示：

```
 遥测   ● 在线   8421 帧   num9/num7   自动: 关   实发
 状态    3 挡   7418/9000 (82.4%)   153.3 km/h   油门 100%  刹车   0%
 决策   HOLD 在功率带内  (82%)
 统计   换挡 12/12 成功  中位 104ms  超时 0  防超转拒绝 1
```

- **`决策`** 那一行是关键：它每帧都告诉你**为什么没换挡**。
  `HOLD cooldown` = 冷却中；`HOLD 防超转` = 降挡会超转；`HOLD 等待上一条确认` = 还在等回执。
- 想停：F11。想退出：F12。

> 第一次上车建议：先按 F11 启用，只跑一条直道，看它升挡是否正常；
> 正常后再进弯试降挡。别一上来就跑完整圈。

## 三、实测结果（2026-11-04，首次上路）

用户实跑约 130 秒，`decisions.csv` 记录：

```
44 次换挡：升挡 24、降挡 20
成功 44/44（100%）
延迟：中位 118ms，最快 116ms，最慢 141ms
相邻换挡最小间隔 259ms（正好等于冷却 250ms，说明没有连发）
1 秒内反向换挡：1 次
1 秒内连续降挡：12 次（重刹时的正常连降）
触发原因：达到升挡转速 24 次、刹车降挡 19 次、滑行降挡 1 次
```

**结论：阶段 4 通过。** 换挡通道稳定、时序一致、没有连发。

### 唯一的一次来回（3→2→3，间隔 942ms）

```
54.799 DOWN 3→2   原因：刹车 100%，转速仅 60%
55.741 UP   2→3   原因：达到升挡转速
```

**为什么不管它**：降挡时按 `转速 × 挡位/(挡位-1)` 粗估落点，得 90%；
等松开刹车给油，90% 已经超过升挡阈值，于是又升回去。

根因是**粗估不准**——真实齿比不是 `挡位/(挡位-1)`。修它需要真实的齿比数据，
那正是阶段 5 要学的东西。现在加一条"猜出来的"防抖规则，等于在错误的估算上
再叠一层补丁，以后会更难拆。

代价很小：一次多余的换挡，约 120ms 无动力；车最后还是落在正确的挡位上。

## 四、决策顺序（每一帧都按这个顺序判断）

| 顺序 | 条件 | 动作 |
|---|---|---|
| 1 | 发动机未启动 / 不在比赛中 | 不动 |
| 2 | 档位 = 11（换挡中） | 不动 |
| 3 | 上一条指令未确认 | 不动 |
| 4 | 速度矢量 Z < 0（在倒车） | 不动 |
| 5 | 档位 ≤ 0 | 不动 |
| 6 | 车速 < 3 km/h 且档位 ≥ 2 | **降挡到 1** |
| 7 | 距上次换挡 < 250ms | 不动 |
| 8 | 油门 ≥ 20%、刹车 < 5%、转速 ≥ 目标 | **升挡** |
| 9 | 刹车 ≥ 30% 且转速 < 68% | **降挡**（赛道主力降挡方式） |
| 10 | 给油 ≥ 25% 但转速 < 42% | **降挡**（动力不足） |
| 11 | 无油无刹且转速 < 45% | **降挡**（滑行） |
| 12 | 以上都不满足 | 不动 |

**为什么第 4 条用速度矢量而不是档位**：
实测 `Gear = 0` 同时表示倒挡、空挡、菜单（200 个有效帧全部 0 km/h）。
只有 `VelocityZ < 0` 才能证明真的在后退。

## 五、参数从哪来

**不是拍脑袋定的，是从你 15 次真实换挡里量出来的：**

| 场景 | 你的实测 | 我们的阈值 |
|---|---|---|
| 全油门升挡 | 转速 **86.0%–90.8%**（中位 88.9%） | 满油门 89% |
| 刹车降挡 | 转速 **56.8%–67.8%**，刹车 100%、油门 0% | 刹车 ≥30% 且转速 <68% |
| 滑行降挡 | 转速 44.3% | 转速 <45% |
| 实测断油点 | 约 **91.9%**（8271/9000） | 升挡点留 3% 余量 |

用 `tools/replay_engine.py` 把录制数据喂给引擎对比：**10/15 次与你同向同挡位，平均时序误差 127ms**。
剩下 5 次的差异都有解释——多半是你在弯中故意压挡，或者我这边阈值略保守。

## 六、首版的已知局限（阶段 5 再补）

1. **不知道车的功率曲线**：89% 是"跟你习惯一致"，不是"物理最优"。
   阶段 5 会学功率曲线，算出真正的换挡点。
2. **没有齿比数据**：降挡前的超转保护用的是粗估（`转速 × 挡位/(挡位-1)`）。
   阶段 5 学会齿比后，这个估算会准得多。
3. **不认弯道**：现在只看转速/油门/刹车，不看横向 G 和横摆。
   弯中该不该升挡，目前只能靠"你在弯里通常不踩满油门"间接实现。
4. **不打滑保护**：轮胎打滑时会把转速推高，可能触发假升挡。阶段 5 加滑移率判断。

## 八、这一步你学到的

**"能换挡"和"换得对"是两层能力，得分开验证。**

阶段 3 证明了"指令送得进去"；阶段 4 才开始处理"什么时候该送"。
如果混在一起做，一旦车换挡不对，你没法判断是通道坏了还是策略错了。

这也是为什么这一版故意做得很笨——只有转速、油门、刹车三个输入。
笨的版本好排查：每个决定都能用这三个数解释。等它稳定了，再往上加学习能力。
