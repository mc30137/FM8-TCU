# 阶段 2：遥测探针使用说明

**这个工具只做一件事：把游戏发给电脑的数据读出来，显示在屏幕上。**
它不发送任何按键、不碰游戏文件、不读游戏内存。关掉窗口就等于关掉它。

---

## 一、先看结论：这一步要验证什么

| 要验证的 | 怎么算通过 |
|---|---|
| 数据格式对不对 | 屏幕显示 `[331B] FM8 (Forza Motorsport 2023) Car Dash` |
| 实时性够不够 | 包率 `59~61/s`，包间隔 `16~17ms` |
| 九个字段准不准 | 档位跟着游戏换挡逐档变；踩油门 `Accel` 到 255；松油门到 0 |
| 偏移表有没有算错 | 底部不出现 ⚠ 告警行 |

四项都对，阶段 2 就过了，可以进阶段 3（手动换挡）。

---

## 二、一次性准备

### 1. 游戏内设置

启动 FM8 → 进入任意赛道（**必须真的在赛道上，菜单里不发数据**）→ 按 ESC 打开菜单：

```
设置 → 玩法与 HUD → 往下滚到 "UDP 竞速遥测"
    Data Out              = 开
    Data Out IP 地址      = 127.0.0.1
    Data Out 端口         = 5300
    Data Out 数据包格式    = Dash        ← 千万别选 Sled
```

> 端口填 `5300` 是为了和探针默认值一致。想用别的端口也行，两边一起改。

### 2. 变速箱设置（阶段 3 会用到，现在先设好）

```
设置 → 难度与辅助 → 变速箱 = 手动（不要选"自动"）
```

选"自动"的话，游戏自己会换挡，外部程序发的指令会被游戏覆盖——这是"时不时换不上挡"最常见的原因之一。

### 3. 关掉其他遥测软件

SimHub、遥测仪表盘、之前装的自动换挡程序，都会抢同一个 UDP 端口。先全部退出。

---

## 三、运行

**双击 `tools\启动探针.bat`** 就行。

窗口里应该先看到几行诊断信息，然后进入实时面板：

```
  Working folder: C:\Users\你\WorkBuddy\...\2026-11-03-19-30-47
  Looking for a working Python ...

   Python 3.8.2 -> C:\Users\你\AppData\Local\Programs\Python\Python38\python.exe
  Press Ctrl+C in this window to stop the probe.

已开始监听 0.0.0.0:5300 …… （Ctrl+C 结束）
```

逐行说明：

- `Working folder` 必须是**项目根目录**（能看到 `tools`、`tests` 那一层）。
- `Python 3.8.2 -> ...` 告诉你用的是哪个 Python、装在哪里。**3.8 就够用**，不用升级。
- 如果这几行之后**没有出现实时面板**，把整个窗口截图发我。

> 为什么脚本要"试跑"而不是简单查一下有没有 python：Windows 10/11 的 PATH 里有一个微软商店的 `python.exe` 占位文件，它**存在但运行后什么都不做**。所以脚本必须真的执行一次 `import sys` 才能确认这个 python 是活的。

如果提示 `No working Python found`：到 <https://www.python.org/downloads/> 下载安装，**安装第一屏一定要勾上 `Add python.exe to PATH`**，装完重启电脑再双击。

想录一段数据以后反复研究，**双击 `tools\录制遥测.bat`**（和普通探针一样用，只是会顺便把原始数据存下来）。
结束时会打印文件名，形如 `fm8_20261104_144732.fm8rec`，就在项目根目录。

也可以手动指定参数：

```bat
python tools\probe.py --record 我的第一圈.fm8rec
python tools\probe.py --duration 60            :: 只跑 60 秒，自动结束
python tools\probe.py --replay 我的第一圈.fm8rec  :: 不开游戏，回放
```

```
 扭矩  Torque=     301 Nm             离合  Clutch=   0 (  0%)

 转速 [███████████████████░░░]  85%      ← ③ 条形图，余光就能看
 油门 [██████████████████████] 100%
 刹车 [░░░░░░░░░░░░░░░░░░░░░░]   0%
──────────────────────────────────────────────────────────────────────────────
 最近换挡（观察档位是否逐档变化、换挡耗时多久）
   19:49:32.667   2 → 3    rpm 3041    108.3 km/h    thr 100%   ← ④ 换挡日志
──────────────────────────────────────────────────────────────────────────────
 ✓ 所有数值通过合理性检查（偏移表与实测一致）    ← ⑤ 自检结论
══════════════════════════════════════════════════════════════════════════════
```

几个细节值得理解：

- **`包率`**：游戏每秒发 60 个包。掉到 50 以下说明有丢包或卡顿，后面做换挡决策会不稳。
- **`间隔 P99`**：99% 的包都在这个时间内到达。如果平均 16.7 但 P99 是 50，说明偶尔会卡 50ms——这会让换挡点漂移。
- **`档位`** 后面会跟一个词：空的时候是数字；显示 `倒挡` 表示 0；显示 `空挡?` 表示收到 11。**这一项我们要重点看**（见下）。
- **`✓ 所有数值通过合理性检查`** 这一行最重要。它背后的检查是：转速不能超红线 5%、车速和速度矢量必须一致、档位必须在 0–12 之间。如果偏移算错了，数字会"看着像真的但很怪"，这些检查会当场喊出来。

## 五、六项检查（按顺序做，每项打勾）

### ① 倒挡 / 1 挡 / 最高挡 到底是什么值

1. 停稳 → 挂**倒挡** → 看 `Gear`（预期 0，但要以实测为准）
2. 回 1 挡 → 看 `Gear`（预期 1）
3. 跑到直线尽头，一路升到**最高挡** → 看 `Gear` 最大到几

**已知情况（2026-11-04 实测）**：FM8 这辆车**没有可选的空挡**，R 和 1 挡之间不能通过升/降挡键进入 N。

这带来一个反面结论和一个正面结论：

- ❌ 参考项目那句 `is_shifting = gear > 10` 在 FM8 上**永远不成立**（那是地平线用 11 表示 N 的语义）。照搬会得到一个"永远认为没在换挡"的程序。
- ⚠️ 但 `Gear == 0` 反而更危险：它可能同时表示**倒挡**、**发车格上车辆还没初始化**、**换挡动画的个别帧**。所以判断"是否在倒车"不能只看档位，必须叠加**速度方向**（`VelocityZ < 0` 才是真的在后退）。

这也是为什么探针要专门记录"最近换挡"：如果升挡时出现 `2 → 0 → 3`，说明 0 会作为中间值出现，我们的逻辑必须能容忍它。

### ② 档位是否逐档变化

加速时看"最近换挡"那几行：`1 → 2 → 3 → 4`。如果出现 `2 → 4` 这种跳档，说明采样有丢失或游戏本身跳档，要记下来。

### ③ 换挡耗时

换挡日志每行都带毫秒时间戳。手动按一次升挡，看两行之间的差值——这就是**真实的换挡耗时**（包括游戏响应 + 变速箱动作）。阶段 4 的决策冷却时间要按这个值来定，不能拍脑袋。

### ④ 九个字段是否符合直觉

| 场景 | 应该看到 |
|---|---|
| 完全停下 | `Speed ≈ 0`，`Accel = 0`，`Brake = 0` |
| 全油门直线 | `Accel = 255`，`Power`/`Torque` 同时上升 |
| 重刹 | `Brake` 接近 255，`Speed` 快速下降 |
| 换挡瞬间 | `RPM` 明显跌落（升挡）或跳升（降挡） |
| 松油门滑行 | `Accel = 0`，`Torque` 变负（发动机制动） |

### ⑤ 包率和稳定性

跑一整圈，观察 `包率` 是否一直在 59–61。记下有没有掉到 50 以下。

### ⑥ 录制 / 回放一致性

1. 用 `--record 圈1.fm8rec` 录一圈
2. 关掉游戏，用 `--replay 圈1.fm8rec` 回放
3. 底部"档位原始值分布"里的帧数、换挡次数应该和录制时一致

这一步通过，说明我们有了**可重复的测试素材**——以后改算法，不用每次都真去开车。

## 六、收不到数据怎么办

探针在 3 秒收不到包时，会直接把排查步骤打在屏幕上。按这个顺序：

0. **窗口是不是一闪就关了？** 把窗口里那几行（`Working folder` / `Using: ...`）截图发我。这一步排查的是"启动脚本没走到运行"，而不是"没数据"。

1. **是不是在菜单里？** 只有真正在赛道上才发数据。
2. **Data Out 开了吗？** 设置 → 玩法与 HUD → UDP 竞速遥测。
3. **端口对得上吗？** 游戏里 5300，探针也 5300。
4. **格式选的是 Dash 吗？** 选 Sled 的话，探针会显示 `[232B] Sled`，而且没有档位/踏板。
5. **端口被占用？** 探针会直接报"无法监听"。关掉 SimHub 之类的软件。
6. **微软商店版的沙箱问题**（最麻烦的一种）：
   - 先试：把游戏里的 **Data Out IP 改成你电脑的局域网 IP**（在 cmd 里运行 `ipconfig` 看 `IPv4 地址`，形如 `192.168.1.23`），探针保持默认监听 `0.0.0.0`
   - 然后放行防火墙（首次运行 Windows 会弹窗，选"允许专用网络"）
   - 还不行才需要回环豁免，到那一步告诉我，我给你具体命令

## 八、这一步你实际学到了什么

三个概念，都在这一个文件里出现了：

1. **字节偏移（byte offset）**
   一个 331 字节的包就像一张 331 格的表格，第 307 格是档位。程序"解析"就是照着一张表去格子里取值。格子号错一位，读到的就是隔壁字段的一半——数字看着像真的，其实是垃圾。这就是为什么参考项目的代码不能直接拿来用：它的表是给 324 字节的包画的。

2. **采样率决定反应速度上限**
   游戏每 16.7 毫秒发一次数据。你踩下油门的瞬间，程序最多要等 16.7 毫秒才知道。所以换挡决策做得再快也没用——真正的瓶颈是数据本身。这也解释了为什么"换挡延迟"里有一大半是游戏自己的变速箱动作时间。

3. **自检比调试便宜**
   探针里那几行 `validate()`（转速不超红线、车速和速度矢量一致、档位在合理范围）不是装饰。它们是"让错误自己喊出来"的机制。程序读错了数据却继续工作，是最难查的 bug —— 参考项目那个 `gear > 10` 的判断就属于这类。

下一阶段（手动换挡）会用到第 3 个概念的升级版：**每条被拦下的动作都要说明理由**。
