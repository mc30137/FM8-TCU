# 阶段 5：车辆适配（齿比 / 扭矩曲线 / 断油转速）

阶段 4 的程序能用，但它对车的了解全是**别人的数字**：升挡 89%、降挡 68%、挡位上限 10。
这些数字在你这台车上刚好合适，换台车就全错。

这个阶段做的事：**让程序自己量出这台车的三个物理参数**，并且只在有把握的时候才用它们。

---

## 一、三个必须解决的问题

### 问题 1：降挡落点靠猜，导致 3→2→3 白换一次

阶段 4 的估算公式是：

```
降一挡后的转速 = 当前转速 × 当前挡位 ÷ (当前挡位 - 1)
```

它隐含假设「相邻挡的齿比按挡位号成反比」。你的车实测：

| | 3 挡 | 2 挡 | 比值 |
|---|---|---|---|
| 实测齿比（转/公里每小时） | 43.6 | 54.8 | **1.26** |
| 阶段 4 的假设 | 3 | 2 | **1.50** |

3→2 时，公式估成「转速 ×1.5」，实际只有 ×1.26。于是在 54.8 秒那次：
估算 90% → 判定"还能再撑"，降挡后实际 78% → 一给油就到升挡点 → 0.9 秒后又升回去。

**误差 19%，足以让保护逻辑和防抖逻辑同时失效。**

### 问题 2：89% 是你的习惯，不是这台车的最优

阶段 4 的 89% 是从你 15 次手动换挡里量出来的中位数——它忠实反映了你的开法，
但和「物理上最晚该在哪升挡」是两件事。真正决定升挡点的是：

> 换到高一挡之后，轮上推力还比当前挡大吗？

这要用**扭矩曲线 + 相邻挡齿比**一起算，而这两样东西都可以从遥测里学。

### 问题 3：`EngineMaxRpm` 不是断油点

你的车名义红线 9000，实际断油 **8271（91.9%）**。如果按 9000 算升挡点，
最后 8% 全是白转，而且会被断油反复截断，车会一顿一顿。

## 二、三个学习器

代码在 `src/fm8_tcu/learning/`，各自独立、可单独测试、互不依赖。

### 2.1 齿比学习 `gear_ratio.py`

**学什么**：每个挡位的「转速 ÷ 车速」比值（单位：转/公里每小时）。

**怎么保证准**：

| 措施 | 原因 |
|---|---|
| 取**中位数**不取平均 | 车速偶有毛刺，平均值会被拉偏 |
| 偏离中位数 25% 的样本丢掉 | 车轮打滑时转速和车速对不上 |
| 只用**稳态**样本 | 换挡、起步、重刹时转速与车速不同步 |
| 样本 ≥ 30 才算「已知」 | 不够就退回旧公式，不硬用半成品 |
| 单调性检查 | 高挡齿比必须更小，违反即判不可信 |

「稳态」的判据是：**同一挡位内，转速/车速这个比值在 0.25 秒内变化不超过 25%**。
这个过滤不是拍脑袋加的——实测效果：

| 挡位 | 全部样本离散度 | 只用稳态样本 |
|---|---|---|
| 3 挡 | 4.34% | **0.50%** |
| 1 挡 | 3.35% | 2.09% |
| 4 挡 | 0.19% | 0.14% |
| 5 挡 | 0.07% | 0.05% |

低挡位（1、2 挡）天生噪声大：起步时离合半联动、驱动轮打滑，这是物理事实，
不是代码问题。所以门槛设成离散度 6%，让它们能被用上；真正错得离谱的值由单调性拦住。

### 2.2 扭矩曲线 `power_curve.py`

**学什么**：全油门时的「转速 → 扭矩」曲线。

**怎么算**：

1. 只采油门 ≥ 85% 的样本（部分油门的扭矩不代表发动机外特性）
2. 按 **100 转**分箱，每箱取中位数 —— 避免"某段转速停留久、样本多"把拟合带偏
3. 用最小二乘拟合二次曲线 `T(r) = a + b·x + c·x²`，`x` 归一化到 [-1, 1]
   （不归一化的话，8000² 会让方程病态到解不出来）
4. **开口必须向下**（`c < 0`）。如果拟合出一条往上翘的曲线，说明数据不是扭矩曲线，直接丢弃
5. 数据不足（< 120 样本 / < 8 个箱 / 覆盖不足 35% 红线）就返回 None

**输出**：峰值扭矩转速、峰值功率转速、任意转速下的扭矩。

### 2.3 断油检测 `rev_limiter.py`

**学什么**：这台车真实断油的转速。

**断油的签名**：全油门、同一挡位、转速一路爬 → 突然掉 ≥ 250 转 → 再爬上去。

判据（四条同时成立）：

```
油门 ≥ 85%  且  挡位没变  且  已连续爬升 ≥ 0.35 秒
且  峰值 ≥ 70% 红线  且  从峰值掉下来 ≥ 250 转
```

「挡位没变」这一条就把**升挡**排除掉了——升挡一定先经过挡位 11 且挡位会变。
「油门 ≥ 85%」把**收油**排除掉。

单次可能是压路肩或打滑，所以要**两次独立确认**才采信。

时间用**游戏自带的时间戳**，不用系统时钟——这样离线按 8 倍速回放录制文件时，
判断结果和实时跑完全一致（这一点实测验证过）。

## 三、学到的数据怎么被使用

关键原则：**学习成果只能让换挡更保守，不能让换挡更激进。**

```
升挡阈值 = 油门曲线给出的基准（0.79 → 0.89）
         ↓ 取更小值
         学习到的物理最优（且最多往下拉 8%）
         ↓ 取更小值
         断油转速 - 1.5%
```

为什么这样设计：

- 如果某次学到脏数据（比如把 0.60 当成最优），最多把升挡点拉到 0.81，不会把车开坏
- 断油保护永远生效，和有没有学好无关
- 学习值**永远不会**把升挡点往上推——往上推需要更多证据，首版不做

降挡落点则是：

```
优先用实测齿比：  降挡后转速 = 目标挡齿比 × 车速
齿比不可信时退回：降挡后转速 = 当前转速 × 当前挡位 ÷ 目标挡位
```

决策日志里会标出来源：`降挡后约 112%（实测齿比）` 或 `（估算）`。

### 齿比不确定时，门槛要更严
这是实跑之后补的一条。在 12000 转那台车上，日志里出现了两次
`DOWN 3 失败 812ms`——指令发出去了，车没降挡。原因是：

```
3 挡 135.7 km/h，2 挡齿比 84.2（样本离散度 10.4%，不可信）
估算落点 = 84.2 × 135.7 = 11424 转 = 95.2%
按 97% 门槛 → 放行 → 但真实齿比可能高 10%，实际会到 104% → 游戏直接拒绝降挡
```

所以规则改成：

| 目标挡齿比 | 用的门槛 |
|---|---|
| 可信（样本 ≥ 30、离散度 ≤ 6%） | 97% |
| 不可信 | **92%** |

宁可晚 100ms 再降，也不要在"差一点"的地方反复撞墙——一次失败的降挡要等 800ms
超时，还挡着后面所有的决策。

这里还牵出一个更隐蔽的 bug：齿比存档读回来时，离散度被算成了一半
（还原样本用的是 ±s 而不是 ±2s），一个 10.4% 的坏数据读回来变成 5.2%，
刚好混过 6% 的门槛，"不可信"被洗成了"可信"，安全余量直接失效。
修好之后，同一帧的判定从 `DOWN` 变成了 `HOLD 防超转（实测齿比，样本不足）`。

另外 `max_gear` 也改了：学到 3 个以上挡位时，**挡位上限 = 学到的最高挡 + 1**。

「+1」这个余量是关键。学到的挡位只可能来自"你开过的挡"，如果程序把学到的最高挡
当成硬上限，它就永远进不了下一挡，也就永远学不到下一挡——自我锁死。
所以你车型的真实挡位数只有 6，而目前只学到 1–5 时，它仍会尝试升第 6 挡。

那如果第 6 挡其实不存在呢？**连续两次升挡失败（挡位没变）就认定当前挡是顶挡**，
之后不再重试。代价是第一次到顶挡时会白按两下，换来的是永不锁死。

（这个 bug 差点留下：你阶段 3 手动测试时已经升到过 6 挡，而录制里只到 5 挡。
如果按最初写法，程序会卡在 5 挡再也上不去。）

## 四、车辆档案

位置：项目根目录 `profiles/car03240.json`（按车的编号命名，不按车名——车名会随语言变）。

内容示例（真实录制跑出来的）：

```json
{
 "car_ordinal": 3240,
 "max_rpm": 9000.0,
 "samples": 4265,
 "ratios": {
  "1": {"ratio": 68.50, "spread": 0.021, "n": 300},
  "2": {"ratio": 54.83, "spread": 0.058, "n": 300},
  "3": {"ratio": 43.57, "spread": 0.012, "n": 300},
  "4": {"ratio": 35.25, "spread": 0.001, "n": 300},
  "5": {"ratio": 28.84, "spread": 0.001, "n": 233}
 },
 "curve": {"bins": {"30": 356.2, "...": 0}, "total": 2100, "max_rpm": 9000.0},
 "limiter": {"rpm": 8271.0, "episodes": 4, "max_seen": 8271.0}
}
```

几个刻意的设计：

- **原子写**：先写 `.tmp` 再 `os.replace`。写一半被 Ctrl+C 杀掉，档案也不会变成半个 JSON
- **每 5 秒 / 每 1500 个新样本存一次**。被强杀最多丢几秒，不会每帧写磁盘
- **换车时先存旧车**再加载新车，跑过的东西不会白学
- **读坏了不抛异常**，当没有档案重新学。学得到的东西不值得让程序崩
- **存的是证据不是结论**：扭矩曲线存的是分箱中位数（可以重新拟合），
  齿比存的是中位数 + 离散度（离散度必须存，否则重启后噪声会被误判成"可信"）

## 五、参数文件

想改参数不用改代码。先生成一份默认的：

```bat
cd src
py -3 -m fm8_tcu.app --write-config ..\params.json
```

然后编辑 `params.json`，启动时带上：

```bat
py -3 -m fm8_tcu.app --config ..\params.json
```

文件里只写你想改的项，其余用默认值。所有值都会**过范围检查**：
`cooldown_s` 写成 0 会被夹到 0.05 并给出提示——这种错误不该靠人发现。

常用字段：

| 字段 | 默认 | 说明 |
|---|---|---|
| `up_pct_low` / `up_pct_high` | 0.79 / 0.89 | 油门 0 / 100% 时的升挡转速 |
| `down_brake_pct` | 0.68 | 刹车时转速低于此值就降挡 |
| `over_rev_uncertain_pct` | 0.92 | 齿比样本不足时的防超转门槛（更严） |
| `cooldown_s` | 0.25 | 两次换挡最短间隔，**不要低于 0.20** |
| `use_learned_shift` | true | 是否使用学习到的升挡点 |
| `max_gear` | 10 | 没有学习数据时的挡位上限 |

## 六、怎么用

和阶段 4 完全一样：双击 `tools\自动换挡.bat`，上赛道，按 **F11** 启用。

区别是浮窗多了一行：

```
3 挡   7418 rpm   153 km/h
UP 达到升挡转速 (89.2% ≥ 88.4% 学习值)
换挡 12/12 成功  中位 118ms  超时 0  防超转拒绝 1
齿比 1-5 挡 · 扭矩 76% · 断油 91.9%
F11 启用/停用   F12 退出
```

**需要跑多久**：

- 齿比：正常跑 1–2 圈就够（每个挡位 30 个稳态样本）
- 扭矩曲线：需要**全油门**样本，正常加速就有；覆盖到 8 个转速箱即可
- 断油：需要**手动把转速拉到断油**两次。自动换挡不会拉到断油，
  所以这项要靠你自己拉一次（或者先关掉自动，手动跑到红线两次）

断油还没学到时，浮窗显示 `断油 待确认`，程序会用名义红线兜底，功能不受影响。

**想关掉学习**：加 `--no-learn`。这时行为和阶段 4 完全一致。

## 八、已知局限

1. **1、2 挡齿比噪声大**（2–6%）。物理原因：起步打滑 + 离合半联动。
   影响：3→2 的落点估计有 2–3% 误差。安全方向（估高 → 更保守），可接受。
2. **扭矩曲线只覆盖你开过的转速区间**。没到过的区间用端点值夹住，不外推。
3. **断油需要手动拉两次**才会学到（自动换挡到不了断油）。
4. **单位跟随游戏设置**。我们只用曲线形状和挡间比值，所以 kW/Nm 或 HP/lb-ft 都行，
   但如果你改了单位，旧档案的绝对值会失真——建议改单位后删掉 `profiles/` 重学。
5. **一辆车一个档案**。同车型不同改装（换变速箱/轮胎）会学到混合数据，
   因为 Forza 的 `car_ordinal` 不区分改装。改装后建议删掉对应档案。
6. **多级降挡仍是一挡一挡来**。重刹从 5 挡到 2 挡需要三次，共约 750ms。
7. **顶挡要按两次空键才确认**。第一次开到最高挡时，程序会尝试升一挡、失败两次
   才认账（约 2 秒）。之后本局不再重试，重启程序会重新试两次。

## 十一、这一步你学到的

**1. 参数要从数据里量，不要从经验里抄。**

89% 这个数字在阶段 4 是对的——因为它是从你的驾驶里量出来的。但它只对**这台车、这个开法**成立。
齿比和断油转速是**物理量**，量一次就永久有效，换车才失效。分清"习惯"和"物理"，
是这阶段最重要的一件事。

**2. 两条独立路径得到同一个答案，才叫验证。**

断油 91.9% 不是我算出来的，是程序从转速掉头里看出来的；然后我又用"最高转速 ÷ 红线"
手工算了一遍，两个数一样。如果只有一个来源，我没法判断是算法对还是巧合。

**3. 学习出来的东西要有"使用边界"。**

程序学到了「最优升挡点 90.9%」，但你的习惯是 89%，而且它只能往下拉 8%。
这不是不信任数据，而是**知道数据可能在什么情况下错**（脏样本、改装、单位变更）。
自动化的第一步不是"让程序自己决定"，而是"让程序在它能证明的范围内决定"。
