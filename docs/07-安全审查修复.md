## 一、四条阻断级

### 1. 顶挡推断会连带禁用降挡，且永不解除

**审查说的**：`_rules()` 在升降挡之前就 `if gear >= ceiling: return`，一旦
`_top_guess` 钉成当前挡，这个挡既不能升也不能降。

**复现**：

```
6挡 54%转 全刹车 → HOLD | 已到档位上限 / gear=6/6
换挡成功后 _top_guess 仍为: 6
```

**根因**：上限检查的位置错了。它本意是"别再往上试了"，结果变成了
"这个挡位到此为止"，连往下走的路一起封掉。

**修法**：
- 上限只拦升挡（`at_ceiling` 只出现在升挡条件里），降挡始终可走。
- `_top_guess` 从 `int` 改成 `(挡位, 时间)`，加 **90 秒有效期**。丢两次按键
  不等于车只有 5 挡，过期后重新给一次机会。
- 换车时 `reset_car()` 清空；成功升到更高挡时也清掉（说明当初猜错了）。

**修复后**：

```
6挡 54%转 全刹车 → DOWN | 刹车 100%，转速仅 60%
10 秒内: 6 | 100 秒后: 10        ← 过期解除
5→6 成功后 _top_guess: (0, 0.0)  ← 猜错会自我纠正
```

> 顺带说一句：这条是审查里最有价值的一条。我上一轮修"挡位越学越少"时
> 引入了 `_top_guess`，只想到了"别锁死升挡"，完全没想到它会把降挡一起锁死。

### 2. 无鉴权的 UDP → 全局键盘注入通道

**审查说的**：默认 `bind(0.0.0.0)`，`recvfrom` 丢弃来源地址，任何本机或局域网
进程发一个 331 字节的包，就能让程序往**当前焦点窗口**发按键。

**核实**：属实。`_addr` 在 `recvfrom` 之后直接丢掉了，`parse()` 只查长度。

**修法**（三层）：
1. **默认只监听 `127.0.0.1`**。要收局域网的遥测必须同时给 `--host 0.0.0.0`
   和 `--allow-from 192.168.1.20`（点名 IP，逗号分隔）。
2. **来源白名单，没有"一键放开"**：即使绑了 `0.0.0.0`，也只有回环和白名单里
   的 IP 能进来，其余丢弃并计数（`foreign_packets`，界面可见）。
   原来的 `--allow-remote` 是布尔开关，一开就完全不校验来源——那不是配置，
   是把刚堵上的洞重新挖开，所以删掉了。
3. **发键前确认前台是游戏**：`SendInput` 是往焦点窗口发的，Alt-Tab 之后
   照样会往微信输入框里塞 num9。现在读前台进程名，不是 `forza*` 就拒发，
   并显示原因。拿不到进程名时放行（宁可偶尔发错，也不要因为读不到就整体失效）。
   可用 `--no-focus-check` 关掉。

另外把 `KeyboardSink.shift()` 的抬键放进了 `finally`：

```python
pressed = False
try:
    if not send_scan(scan, up=False):
        return False
    pressed = True
    time.sleep(self.hold_ms / 1000.0)
    return True
finally:
    if pressed:
        send_scan(scan, up=True)      # 无论中间发生什么，都要抬起来
```

原来的写法一旦 `sleep` 中途抛异常，那个键就一直处于按下状态——用户在游戏里
会遇到"车自己一直升挡"，而且找不到原因。退出时还有 `release_all()`。

**没做的**：没有给 UDP 加签名/令牌。理由是它只能防"不知道协议的进程"，
而真正的边界是"谁能连上这个端口"。绑回环 + 来源白名单已经把面收敛到本机，
再加一层密钥只是把复杂度转移给用户（每次启动要配对）。如果以后真要做
局域网遥控，应该上 token + 白名单双管，而不是现在临时加个字段。

### 3. 一帧 NaN 遥测可让命令行版直接崩溃

**审查说的**：`struct.unpack` 会把 `0x7FC00000` 原样读成 NaN，一路穿过所有
区间判断（NaN 与任何数比较都是 False），最后在 `int(rpm // 100)` 抛 `ValueError`，
`app.py` 主循环只捕获 `KeyboardInterrupt` → 进程退出。

**复现**：

```
解析成功: True  usable: True  rpm_pct: nan
learn 抛出 ValueError: cannot convert float NaN to integer
```

**修法**（两道）：
1. **协议层**：`parse()` 增加 `_plausible()`——所有 float 字段必须 `isfinite`，
   挡位 ≤ 11，转速非负。不合法整包丢弃，`bad_packets` 计数。
   顺带删掉了 `layout_ok` 这个"设了但从不置 False"的死字段。
2. **学习层**：三个学习器各自再 `isfinite` 一次。不是重复劳动——学习器可以被
   单独调用（测试、脚本），不能让它们假设上游一定干净。
3. **主循环**：`app.py` 兜住异常并计数。协议层是网，这是网下面的垫子。

**修复后**：

```
rpm=NaN      → parse: None（丢弃）
torque=Inf   → parse: None（丢弃）
gear=200     → parse: None（丢弃）
rpm=-1       → parse: None（丢弃）
正常          → parse: 接受
```

端到端验证：发 2 个坏包 + 1 个正常包，面板显示 `1 帧  坏包 2`，进程存活。
**改之前这一下就退了。**

### 4. 「遥测断流 300ms 立即停手」名不副实

**审查说的**：`stale()` 只被 `snapshot()` 用于显示，`_decide()` 发键前不看它。
平时"看起来停手"只是因为循环由收包驱动——没有包就恰好没有动作，这不是看门狗。

**复现**：

```
stale: True
断流 10 秒后仍发送: ['UP']     ← 应为空
```

**修法**：把"停手"变成显式的门，而不是数据流的副作用。

```python
gap = now - self.last_frame_t
fresh = gap <= STALE_S
if not fresh and self.engine.pending is not None:
    self.engine.pending = None      # 断流前的回执不可信，作废
    self.watchdog_trips += 1
...
self._decide(tele, now, allow_send=fresh)
```

`_decide()` 里还有第二道 `if not allow_send or self.stale(): return`。
这样即使将来有人从别的路径调用它，也不会漏。

**为什么没加独立线程**：发送动作本身在主线程，加一个线程也只能"清 pending +
置标志"，真正的拦截点还是在收包路径上。而且断流时游戏已经暂停了，不存在
"必须在一帧内停下"的场景。写清楚这个判断，比加一个看起来更安全的线程更诚实。

## 三、没有改的，以及为什么

审查里有些建议我判断**不该照做**，理由写在这里，方便以后翻案。

**1. 把「档位变了」改名叫「期望方向变化率」。**
名字更诚实，但它只是把不确定性搬进了名词里，没有减少不确定性。玩家手动换挡
确实会污染统计，但概率很低（用自动换挡时手不会去碰挡杆）。真正该做的是
**不要把成功率当安全依据**——现在它只用于显示，不参与任何决策。这一点已经成立。

**2. 顶挡改用「已观测挡位集合 + 齿比表」推断。**
这已经是主依据（`_learned_ceiling()` = 学到的最高挡 + 1）。失败计数只是
"别反复空按"的补充，现在又有 90 秒有效期。再复杂的推断需要知道车的挡位总数，
而游戏不提供这个字段。

**3. 数据目录迁到 `%APPDATA%`。**
绿色软件"拷到哪都能跑"是明确的用户价值，迁目录会让现有档案失效。
折中：默认仍在 exe 旁边，写不进去才退到 `%LOCALAPPDATA%`，并在界面上说明。
这样两种诉求都满足，代价是多一条分支。

**4. 单线程加决策线程。**
主循环里最重的是 `SendInput + sleep(60ms)`，它本身就是"换挡期间不该做别的"
的语义。拆线程需要给发送加锁，反而多一处可能出错的地方。真要提升实时性，
应该缩短 `hold_ms`（实测 60ms 足够）而不是加线程。

**5. 签名 exe。**
需要代码签名证书（每年几百到几千元），对一个自己用的小工具不划算。
替代方案是 `error.log` + 版本号显示，至少能回答"跑的是哪一版"。

**6. 给 `Telemetry.values` 做真不可变。**
它只在 `parse()` 里构造一次，之后没有人写。加 `MappingProxyType` 会让
每帧多一次对象分配（85 帧/秒），收益接近零。改了 docstring 说明实际约定。

## 六、这一阶段真正学到的东西

**1. 安全机制不能只是"看起来有"。**
`stale()` 这个函数从阶段 4 就存在，注释写着"遥测多久没更新就停手"。
它被调用、有返回值、界面上有对应文案——唯独没有拦过任何一次发送。
这类"文档写了、注释声称了、代码没实现"的落差，比明显的 bug 危险，
因为读代码的人会以为这块已经处理过了。

**2. 修一个 bug 时，要问"它还管着什么"。**
上一轮加 `_top_guess` 是为了防止"挡位越学越少"，只想着升挡。
结果它顺手把降挡也锁了。现在改成"只拦一个方向"，并在注释里写明为什么。

**3. 校验要放在最外层。**
NaN 是在 `int()` 那一步炸的，但那不是它该被拦住的地方——那里已经没有上下文了。
放在 `parse()` 里，坏包连一个对象都建不出来，下游所有代码都不用再想这件事。
**越早拒绝，后面要做的判断越少。**

## 七、第二轮复审（HUD 改动之后）

接手 HUD 平滑显示的改动后，复审又发现三条阻断级问题。这一轮全部核实并修复，
其中第一条是**上一次修复自己引入的回归**。

### 1. `gear=11` 被当成无效帧 → 回执系统整体失效

上一次为了修"菜单帧误结算"，把可结算的挡位写成 `1 <= gear <= 10`。
但 11 是"换挡中"，恰恰是等回执的那个状态。真实录制里 15 次换挡 **15 次都经过 11**
（138 帧，占 3.2%），于是每次换挡都在过渡帧被静默作废：

- 统计永远显示"未换挡"，延迟中位数失效
- 日志里没有换挡结果行（README 却让人"先数失败有几行"）
- 顶挡的失败计数永不触发，TTL 那套逻辑成了死代码

现在 `1 <= gear <= 11`，11 走"保持等待"；只有 `gear <= 0`（菜单/空挡）才作废。
同一份录制的回放结果：**0 条记录 → 17 条、12 成功、中位 269ms**。

### 2. pending 的归属：从"决策时"改成"发送后"

`_command()` 在产生换挡意图的瞬间就写了 pending / last_action / last_shift_t，
但发不发得出去要到 service 才知道。焦点检查拒发、断流恢复首帧、SendInput 失败
这三条路径会留下假 pending，0.8 秒后凭空多一次超时，两次就能把顶挡钉 90 秒。

实现成一次小事务：`_command()` 在改状态**前一行**存快照，service 发现没发出去
就 `rollback_command()`。快照必须取在 `_command` 里而不是 `process()` 之前——
同一帧可能先用 `_resolve` 结算了上一条、紧接着又发新指令，快照太早会把已经
结算掉的 pending 复活，下一帧按旧挡位再记一次成功（`test_rollback_does_not_revive_resolved_pending`）。

### 3. 灯条标定：满格改成 `min(断油点, 满油门升挡点)`

按断油点标定，红区（0.90）落在升挡点（0.89）之上，而控制回路的本职就是在
升挡点把转速切走——灯条永远亮不到红色。4265 帧真实数据里红区只有 26 帧，
还是手动拉到断油才出现的。

现在取两者中先到的那个（改装车可能断油更早），未学断油时用升挡点兜底。
验收从"手工构造比例"改成"真实参数下升挡点前必须亮红、到点必须闪"。

### 其余（复审 🟡 项）

| 问题 | 处理 |
|---|---|
| 顶挡猜测可能逐挡下移 | 判断改用 `_learned_ceiling()`，只看学习值，不看猜测 |
| `--allow-remote` 一开就完全不校验 | 删掉，改成 `--allow-from IP[,IP]` 白名单；回环永远放行 |
| 抬键失败静默 | 记 `last_error`；`release_all()` 同样记录 |
| `_decide` 里恒为 False 的 `self.stale()` | 删掉，只留显式的 `allow_send` 门 |
| Tk 回调异常不进日志 | 设 `root.report_callback_exception`，`stderr` 为 None 时不抛 |
| 60Hz 定时链没有生命周期 | 只在 HUD 打开时续订，`quit`/出错时 `after_cancel` |
| exe 无版本资源 | 打包时生成 `VSVersionInfo`，右键属性可见版本；`dist/version.txt` 记 commit |
| 临时日志进了仓库 | `git rm --cached` + `.gitignore` 加 `tmp_*.csv` |

### 设计取舍（复审追问的四点）

1. **pending 属于谁**：属于"已发出的按键"。引擎只负责产生意图，service 负责
   把它变成事实；没变成事实就回滚。
2. **gear=11 是过渡态**：现在两层一致（protocol 允许到 11，engine 也接受 11）。
   分类没有收敛到 protocol，但两边都写明了理由，并有 `UP → 11 → 4` 的端到端测试。
3. **灯条的验收标准**：满格 = 实际升挡点，闪 = 该升挡了。断油只作为"可能更早"
   的上限参与 min，因为它本来就是物理上限。
4. **二进制与提交绑定**：`dist/version.txt` 写版本、commit、构建时间；
   exe 内嵌同样的版本号。仍然不签名（证书成本），但至少能回答"你跑的是哪一版"。
