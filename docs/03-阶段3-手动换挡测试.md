# 阶段 3：手动换挡测试

**这一阶段只回答一个问题：我们能不能把手动换挡指令送进 FM8，多快、多可靠。**

先不碰"什么时候该换挡"——那是阶段 4。现在把"通道"和"策略"分开测，
出问题时才能一眼看出是哪一半坏了。

---

## 一、前置设置（游戏里）

### 1. 变速箱必须是手动

```
设置 → 难度与辅助 → 变速箱 = 手动
```

选"自动"的话游戏自己会换挡，外部指令会被覆盖，你会看到"每一条都超时"。

### 2. 确认换挡键绑在哪

FM8 默认：

| 动作 | 默认键 |
|---|---|
| 升挡 | 小键盘 9 |
| 降挡 | 小键盘 7 |

如果你改过，或者想换成别的键，改游戏设置或者用参数告诉工具：

```bat
python tools\manual_shift.py --keys e:q
python tools\manual_shift.py --keys "[:]"
```

**小键盘键有个坑**：NumLock 关闭时，小键盘 7/9 会被系统当成 Home/PageUp，
游戏收不到。工具启动时会检查并提示。

---

## 二、运行

双击 **`tools\手动换挡测试.bat`**。

会同时出现两个东西：

1. **命令行窗口**——完整面板（切换出去才看得到，切出去游戏会暂停）
2. **屏幕左上角的置顶小浮窗**——游戏画面上直接显示档位、上次结果、成功率

浮窗是**鼠标穿透**的：点它不会让游戏失焦，也不会挡住你的操作。

> **如果浮窗看不见**：先把游戏改成「**窗口化**」试一次。如果窗口化能看到、无边框看不到，
> 那就是 Windows「全屏优化」在作怪——它把无边框窗口当成独占全屏渲染，浮窗画不上去。
> 彻底解决办法：右键 FM8 的 exe → 属性 → 兼容性 → 勾选「禁用全屏优化」。
>
> 工具启动 3 秒后会**自检**并打印一行结论：是"没有窗口压在上面"还是"被游戏盖住了"，
> 按那行提示处理即可。看不看得见浮窗都不影响功能——**声音提示始终有效**。

### 声音提示

不用看屏幕也能判断结果：

| 声音 | 含义 |
|---|---|
| 高音短促（叮） | 升挡成功 |
| 中音短促（咚） | 降挡成功 |
| **低音长响** | **失败 / 超时**（档位没变） |

关掉声音加 `--mute`。

### 按键

| 按键 | 作用 |
|---|---|
| **F6** | 升挡（发一次升挡指令） |
| **F5** | 降挡 |
| **F7** | 切换「演练 / 实发」——演练模式只显示不发送 |
| **F12** | 退出并打印总结 |

**建议流程**：

1. 先按 F7 切到**演练**，按几次 F6/F5
   → 浮窗上出现"升挡（演练，未发送）3→4"
   → 这一步只验证"按键能被检测到"，不会真的动挡
   → **演练不计入成功率**，别把它当成测试结果
2. 再按 F7 切回**实发**，正常开，按 F6 升挡
3. 连做 10 次升挡 + 10 次降挡
4. 按 F12 看总结

---

## 三、屏幕怎么读

```
 遥测    84.5 帧/秒   ● 在线
 输出    num9 / num7   模式: 实发
──────────────────────────────────────────────
 当前    档位  3      转速   7418/9000 (82.4%)      车速  153.3 km/h
         油门 100%   刹车   0%   离合   0%
──────────────────────────────────────────────
 上次    升挡  3→4  成功  延迟 72 ms
 统计    成功 12/12  超时 0   中位 71ms  最快 70ms  最慢 74ms
         升挡 2→3  70ms  ✓
         升挡 3→4  71ms  ✓
```

- **`延迟`** = 你按下 F6 的那一刻，到遥测里档位真的变了的那一刻。
  它包含：按键注入 + 游戏输入响应 + 变速箱动作（实测约 70ms）。
- **`超时`** = 1.5 秒内档位没变化。说明指令没生效。

## 四、结果判读

### 实测结果（2026-11-04，键盘通道）

```
成功 20/20    超时 0
中位 104ms    最快 97ms    最慢 124ms

升挡 1→2 113ms   2→3 106ms   3→4 117ms   4→5 124ms   5→6 104ms
降挡 6→5 104ms   5→4 104ms   4→3 104ms   3→2  97ms   2→1 105ms
（升/降各两轮，共 20 次）
```

**结论：键盘通道可用，阶段 3 通过。**

这个延迟拆得开：实测变速箱换挡本身约 70ms，剩下约 34ms 是
"按键注入 → 游戏响应"的开销。两者相加正好是 104ms 的中位数。

> 注意：**必须用 F5/F6 触发**。用手柄自己换挡，工具不会记录（它只统计自己发出的指令）。
> 如果在你按下 F6 的同时又用手柄换挡，可能会被误判成一次成功——测试时只用一个。

### 判读表

| 现象 | 含义 | 怎么办 |
|---|---|---|
| 成功 20/20，中位 80–200ms | ✅ 通道可靠 | 进阶段 4 |
| 偶尔超时（20 次里 1–3 次） | ⚠️ 键盘注入不稳 | 先试 `--hold 80`；不行就上 vJoy |
| 全部超时，档位毫无变化 | ❌ 指令根本没进游戏 | 见下面排查 |
| 延迟忽大忽小（100ms 与 400ms 混杂） | 帧率波动或游戏卡顿 | 记录下来，阶段 4 的冷却按最大值定 |

### 全部超时的排查顺序

1. **键位对不对**：游戏里实际绑的是不是小键盘 9/7？用 `--keys` 改成一致的
2. **NumLock 开着吗**（如果用小键盘）
3. **变速箱是手动吗**
4. **权限**：如果游戏以管理员运行，工具也必须以管理员运行
   （Windows 的 UIPI 会阻止低权限程序向高权限窗口发输入）
5. **按键保持时间太短**：试 `--hold 80` 或 `--hold 100`
6. **游戏用 Raw Input 且只认物理设备**：那就只能上 vJoy

## 五、关于 vJoy

你机器上目前**没有安装 vJoy**（`C:\Program Files\vJoy` 不存在）。

它是"虚拟方向盘"方案：注册一个 DirectInput 设备，让游戏以为有个真的换挡器。
好处是离散按钮不会漏、不干扰你的手柄摇杆；坏处是要装驱动、要重启、还可能在
Forza 的设备枚举里和真实手柄打架。

**所以策略是**：先用键盘把整条链路跑通。只有当键盘实测失败率明显偏高时，
才值得去装 vJoy。这也是"一次只改一个变量"的原则。

---

## 六、这一步你学到的

**"能不能用"和"好不好用"是两个问题。**

键盘注入能跑通，不代表它可靠——另一个项目为它写了 4 种注入方式，说明在
Forza 上它是会漏的。所以这一阶段不能只测"成功一次"，要测"20 次中成功几次、
延迟分布如何"。

**用成功率而不是单次成功来判断通道质量**，这是工程和"我试了一下好像行"的区别。
